## Frontend & Module Boundaries

1. **Keep `App.tsx` thin:** No new orchestration in the shell — a new state machine, IO workflow, or subscription belongs in a focused module (`documentViews.ts`, `appTabs.ts`, `useDocumentCoordinators.ts`, `*Coordinator.ts`, `*Runner.ts`, `documentOpen.ts`, `fileTreeActions.ts`). `App` composes owners and renders layout; it must stay under the root 500-line target (`scripts/module-size-baseline.json` has no entry for it, and `check-module-size.mjs` rejects an obsolete allowance).
2. **The shell never subscribes to document text:** `DocumentStore` owns `workspace`, `docs`, `docVersions`, `dirtyTabIds`, `saveStateByTab`, `normalizationByTab` outside React. `App` uses only `useWorkspace` / `useDirtyTabIds` / `useSaveStateByTab` / `useNormalizationByTab`; `useActiveTabDoc`, `useDocVersion`, and `useDocumentStats` are consumed by the components that actually render the text (status bar, find bar, outline controller). `dirtyTabIds` must keep the **same array reference** while an already-dirty tab keeps changing — it is rebuilt only when a tab's dirty boolean flips or the tab set changes (`test/App.renderPerf.test.tsx`, `test/documentStore.test.ts` pin zero shell renders per materialized keystroke).
3. **Hot-path performance (`documentMaterializer.ts`, `editorStatusStore.ts`):** `EditorDocumentUpdate` never carries a full document string. Pull `view.state.doc.toString()` on the 250ms trailing materializer cadence (bounded by `maxWaitMs = 2000`) and flush before save/close/delete or outgoing tab switches with pending edits. Route cursor/mode updates through `editorStatusStore` (`sameEditorStatus` deduplicated).
4. **View ownership & budget (`editorRegistry.ts`):** Hosts and `EditorView`s live in the registry; a React `ref` callback only calls `bindHost`. Above `MAX_LIVE_EDITOR_VIEWS` (8) the least recently activated *clean* background tab is released (enforced both by `activateTab` and after every `ensureViews`, because new/open/restore tabs mount views without activating them) — its final text is flushed into `DocumentStore` first, real CodeMirror views keep their `EditorState` with Live Preview decorations stripped (`setLivePreview(false)`) so Undo/Redo history, rope, and mode survive eviction, the host div stays mounted, and activation remounts/rebuilds the view through `revive()` restoring caret, `scrollTop`, scale policy, and editor settings (`discardDetachedState` invalidates preserved state on background document reloads). Never evict a dirty tab, a tab with a pending normalization, or the active tab. Fake views in `appHarness` have no `scrollDOM`, so read `view.scrollDOM?.scrollTop ?? 0` and guard the write.
5. **Per-tab autosave (`autosaveScheduler.ts`):** Every dirty tab owns its timer; switching tabs must never cancel another tab's pending write. Arm from materialization (and on a dirty flip), re-check existence/path/dirtiness/`canAutosave` at fire time, and `cancel` on close or on a save that leaves the tab clean.
6. **Overlays own the keyboard (`Dialog.tsx`):** Settings, About, version history, the command palette and quick open all render inside `Dialog`. It records the opener, moves initial focus into the box (`initialFocusRef` → `[autofocus]` → first focusable), traps Tab/Shift+Tab, marks `.topbar`/`.workspace-body` `inert`, and closes on Escape (unless the event commits an IME composition). Never add `autoFocus` inside a `Dialog` (React's commit-phase focus steals the opener capture) and never restore `inert`/focus handling into individual modals. `isAnyModalOpen()` + `App.tsx::dialogOpenRef` gate `useGlobalShortcuts`: while a dialog is open only `preferences` and `quick-open` still run, so `Cmd+W` can never close the document behind the overlay (`test/Dialog.test.tsx`, `e2e/a11y-ergonomics.spec.ts`).
7. **Keyboard semantics are part of the contract:** the file tree is a WAI-ARIA tree (`role=tree/treeitem`, `aria-level`/`aria-expanded`/`aria-selected`, roving `tabindex`, `fileTreeKeyboard.ts` intents, Shift+F10 menu) and the tab strip exposes `role="tablist"` via `.topbar-tablist-owner`'s `aria-owns` over `role="tab"` items while keeping `.tab-close` as a sibling button outside `tablist` ownership — never nest interactive content or place `role="button"` inside `role="tablist"`. Background `inert` is resolved at style recalculation, so focus restore retries once on the next frame (`docs/memory/gotchas-desktop.md`).
8. **Feedback & i18n:** Route user notifications through `services.reportError` / `services.notifySuccess` (never call `window.alert` directly; rate-limit per-change recovery errors in `recoveryWriter.ts`). Keep i18n in desktop (`useT` / `t`) and pass localized labels to the engine via `EngineOptions`.
9. **Multi-window safety:** Scope window-targeted Tauri listeners (`menu-command`, `open-file`, `workspace-changed`, `session-flush`) with `listenTarget()` (`AnyLabel`) in `desktopServices.ts`. Gate `restoreDrafts()` on `windowScope.isMainWindow()`, while `restoreSavedSession()` runs per window shard. Named-file recovery keys (`session.ts::recoveryKeyForPath`) include non-main window labels so two windows editing the same file never overwrite or delete each other's crash-recovery records.
10. **Logging ownership (`logger.ts`, `logPath.ts`, `globalErrorHandlers.ts`, `ErrorBoundary.tsx`):** Logging is **opt-in** (`settings.loggingEnabled`, default off; Rust `LOGGING_SETTINGS_KEY`) — a default install must create no log file, so no module may write a record before the user turns it on, and `OMD_LOG` is not consent. The desktop host owns logging; `@omd/engine` stays silent. Keep handled errors at `warn` via `services.reportError` (render them with `errorMessage`, which reads a typed command error's `message` rather than stringifying the object); log polling outages/recoveries and divergence changes once per transition (`fileTabWatcher.ts`, `saveDiagnostics.ts`). Route frontend records through `getGlobalLogger()` (batched `log_frontend` IPC, flushed before `sessionFlushAck` on quit) and wrap paths with `pathField` / `pathsField` (`test/logPathSourceGuard.test.ts` forbids raw `path=`/`paths=` literals). `logging.ts` is policy only (no React import); the `useLoggingState` hook lives in its own module so non-React consumers do not pull React into their graph. Logging policy stays out of `desktopServices.ts` (the wire layer only resolves destinations and invokes; the pre-export flush belongs to `appDiagnosticsActions.ts`). Never log document content or hot-path editor events. Untrusted thrown values go through `describeThrown`, which reports structure (type, key names, message/stack) and never serializes a payload; the export promise "no document content" depends on that.

## Security & Authority Contract

- **Renderer-specific delta:** UI callers consume the host's handles/ids and display paths; they never treat a path as permission. Picker, OS-open, and drag-drop paths are resolved by Rust before the renderer sees a handle.
- **Authorization failures are UI state, never success.** Surface `Unauthorized`, `Missing`, `Moved`, and `PermissionDenied` with Retry/Re-pick. Never use `.catch(() => {})` or cache a rejected grant as resolved; that was the `useWorkspaceWatcher` failure mode and is now guarded by tests.
- **Asset URLs are host-minted.** Use the host-provided local-image resolver; never construct filesystem `asset:`/`file:` URLs in the renderer.

The shared principle and target contract live in the root guide and [`docs/superpowers/specs/2026-11-24-security-model-design.md`](../../docs/superpowers/specs/2026-11-24-security-model-design.md). The current interim per-window scopes are in [`src-tauri/AGENTS.md`](./src-tauri/AGENTS.md).

## CodeMirror Host & CSS Rules (`Editor.ts`, `tightSelection.ts`, `styles.css`)

- **No stock `drawSelection()`, `closeBrackets`, `indentOnInput`, or `autocompletion()`:** Mount vendored `tightSelection()` (guarded by version/geometry tests in `test/tightSelection.test.ts` — account for `.cm-content` 16px/24px padding and `view.documentTop`).
- **Keep `highlightActiveLine()` mounted** with `.editor-host .cm-content .cm-activeLine { background: transparent }` in `styles.css` (required by focus mode `.cm-line:not(.cm-activeLine)`). Repaint `.cm-line.omd-codeblock.cm-activeLine` background and `.cm-line.omd-blockquote.cm-activeLine` `--omd-bq-image` quote bar.
- **No vertical margins on `.omd-block`:** Use wrapper vertical padding and put borders/overflow on `.omd-block-body` (`test/blockWidgetLayout.test.ts`).
- **Theme via CSS variables only:** Never enable CodeMirror's `{ dark: true }` facet. Drive selection and caret colors from `--omd-selection-bg` and `--omd-cursor`, declare `color-scheme` on every theme block in `styles.css`, quote font names via `settings.ts::cssFamily`, and sync native window appearance via `setWindowTheme` only after initial settings load.
- **Read-only is advisory:** Guard document-changing commands and asset writes with `view.state.readOnly`; selection/status-only transactions remain permitted.
- **View lifecycle (`Editor.ts`, `App.tsx`):** Open/reload uses a fresh `EditorState`, with the path synchronized before initial image resolution; undo history must not cross documents. Destroy views and clear retained references on cleanup. Keep window listeners stable and read changing state through refs.

## Shortcuts, Paste & Image Handling

- **Shortcut single source (`shortcuts.ts`, `commands.ts`):** `WINDOW_SHORTCUTS` drives both palette labels and `App.tsx` window keydown dispatch. Editor-owned bindings (`undo`, `redo`, `cut`, `copy`, `paste`, `pastePlainText`, `select-all`) belong in `EDIT_SHORTCUT_BINDINGS` (display/drift-only, never `WINDOW_SHORTCUTS` to avoid double-fire). Guarded by `test/crossLayerMenu.test.ts`.
- **Two keyboard channels, two guards (`useGlobalShortcuts.ts`):** native menu accelerators arrive through `services.listenMenu`, **not** `keydown`, so dialog isolation must be enforced on both paths. While `isDialogOpen()` or `isAnyModalOpen()` is true, `keydown` allows only `DIALOG_SAFE_COMMAND_IDS` and the menu channel allows only `DIALOG_SAFE_MENU_IDS` (overlay switching + app-lifecycle items: preferences, quick-open, about, check-updates, export-diagnostics, open-log-folder, quit). Everything else — `close`, `save`, `new`, `bold`, `recent:*` — must be dropped, or `⌘W`/`⌘S` from the menubar mutates a document hidden behind Settings. Guarded by `test/App.menuIsolation.test.tsx`.
- **Copy, paste & image invariants (`clipboardCopy.ts`, `clipboardPaste.ts`, `pasteAssets.ts`, `imagePaste.ts`, `Editor.ts`):**
  - `clipboardCopyExtension` writes both `text/plain` (exact Markdown source) and `text/html` (`<div data-omd-markdown-copy="1">…</div>` body rendered via `exportHtml`, capped at `MAX_RICH_COPY_CHARS`) in Live Preview outside verbatim ranges; `clipboardPasteExtension` strips that internal HTML marker so internal copy→paste stays byte-for-byte lossless while external apps receive rich HTML.
  - `clipboardPasteExtension` is the single rich-paste event owner (captures macOS context-menu target, reads clipboard payloads, runs engine `prepareSmartPaste`/`planSmartPaste`); `imagePasteHandler` handles image drag-and-drop and the file picker.
  - Write pasted image batches via `write_paste_assets` → `commit_paste_assets` / `discard_paste_assets` (requires saved `documentPath` and grants asset scope before inserting relative `assets/...` Markdown).
  - Serialize per-view async paste operations via `pasteJob.ts`, capture/revalidate `tabId`, `documentId`, and selection ranges, and always pass an explicit `selection: { anchor }` on custom `view.dispatch` calls (prevents `assoc = -1` leaving the caret before the insert).

## Guarded Save, Scale Tiers & Updates

- **Guarded document IO & single autosave gate:** Use only `statDocument`, `readDocument`, `readDocumentStreaming`, `readDocumentVersion`, and `saveDocument`. Gate all autosaves through `documentSaveCoordinator.ts::canAutosave` (paused during conflict, save failure, or pending ordered-list normalization). Update session baseline atomically on `Saved` only.
- **Identity before reset (`App.tsx::resetTabDocument`):** Keep tab ids stable, bump `documentId` for a new/reloaded document, and commit that identity before resetting the view. Roll back session/projection on reset failure; discard pending materialization after successful reset. Update callbacks carry their captured identities, never the active tab's.
- **Async completion (`normalizationCoordinator.ts`, `documentSaveRunner.ts`):** Revalidate tab, document, view, and normalization notice via the existing target guards before dispatch or UI resync. Accept normalization only after a successful explicit save; cancellation/failure keeps it pending. Recovery continues while normalization pauses disk autosave. Old save completions must not clear newer edits, recovery, or dirty state.
- **Conflict boundary:** Watcher/poll results are hints, not permission to overwrite; Rust's guarded save owns the final compare. Use save-state reducers to update version and clean baseline together for the same document, preserving edits made during the save.
- **Large-document scale policy (`documentScaleRegistry.ts`, `editorScalePolicy.ts`):** Call the applier from `resetTabDocument` and `ensureViews`. Its per-view engine facet (`performancePolicy`) is authoritative for every tab; the app must never rewrite the process-global `setBlockRenderBudget` / `setSafeModeRendering` defaults (no activation-order mirror, no background-view clobbering).
- **Hot Exit (`sessionRestore.ts`, `appSessionFlush.ts`, `appSessionInit.ts`):** A normal quit writes every dirty buffer through `recoveryWriter.persistNow` and records `hotExitTabs` (ordered `{kind, path, recoveryKey}`) + `activeTabIndex` in the same shard, so the next launch reopens every named and dirty untitled tab in place, marks the adopted buffers dirty against their disk baseline, focuses the same tab, and **never** shows the crash prompt. `extractSessionState(ws)` without a dirty-key map must keep returning exactly `{ folder, openPaths, activePath }` (legacy shards and `sessionRestore.test.ts`). `restoreSavedSession` returns the set of recovery keys it claimed; `restoreDrafts(host, claimed)` skips those and only offers genuinely orphaned records. A claimed draft is re-armed under its tab's own `recoveryKey` before the source record is deleted; equal keys already are that copy and are kept.
- **Draft recovery (`appSessionInit.ts`, `recoveryAdoption.ts`, `recoveryWriter.ts`, `recoveryCleanup.ts`):** The main window restores the session shard first, then offers **every** recovery record not claimed by a Hot Exit; a record is deleted only after adoption, an explicit decline, or empty contents (a failed read keeps it). A record's identity comes from the stored envelope, not its filename: adoption matches a draft that recorded a path to the tab holding **exactly** that path, and only a path-less draft (untitled or pre-header legacy) falls back to `recoveryKey` matching. Before adopting a path draft, load its still-lazy session tab (`ensureDraftTarget` → `loadLazyTab`) so the draft lands in a tab with a real disk baseline; adoption never targets a `lazyFile` tab, whose next activation would refetch the file over the draft. It then reuses the sole pristine untitled tab, and otherwise opens one tab per additional draft — never overwrites existing content. Because the mounted draft is memory-only, the source record is deleted only after the draft has been re-armed under the adopted tab's `recoveryKey` (equal keys already are that copy and are kept; a failed re-arm keeps the source record; the re-armed record keeps the envelope's path, so a draft whose file tab could not be loaded still returns to it next launch); a failed delete leaves the record for the next launch instead of aborting the remaining drafts. `recoveryKey` must be a bounded ASCII file name valid on Windows, macOS, and Linux (slug + 64-bit identity hash; never a reserved device name, traversal name, separator, colon, or >255-byte component), and Rust `valid_key` rejects anything that could escape the recovery directory. Closing a discarded tab awaits `recoveryWriter.forget`'s in-flight write (a late write must not recreate the deleted record) before deleting the draft; save-as cancels the old-key pending write (re-arming a still-dirty tab under its new key) and then clears the record under the previous key as well. File-tree rename runs `fileTreeActions.ts::migrateRecovery`: stop old-key writes, persist a dirty tab under its new key through the writer's queue, then delete the old record only after that write succeeds (`FileTree.menu.test.tsx`). Writer dedup compares both key and contents and skips only when no pending or in-flight write can overwrite that copy. A tab's writes are serialized per tab so a slow write of older contents cannot land after a newer draft; exact-string path matching in adoption is deliberate — spelling variants degrade to a fresh tab, they never lose content (see gotchas). Every cleanup delete goes through `clearRecoveryRecord`, which logs a failed delete instead of raising an unhandled rejection.
- **Updater (`updateCoordinator.ts`, `updateRestartReadiness.ts`):** Never silent or automatic. Both `requestInstall()` and `install()` run the session-flush and readiness gate (`dirty`, `conflict`, `saveFailed`, `pendingNormalization`, `opening`, `saving` block install).

## Verification

```sh
pnpm test:desktop
pnpm build:web
PW_PORT=9431 pnpm test:e2e
```

- `pnpm build:web` must finish with zero Rollup warnings: `viteChunks.ts` keeps the eager graph (`index`, `vendor-react`, `vendor-codemirror`, `vendor-tauri`, `vendor-toastify`) under the 700 kB budget and leaves Shiki grammars, CodeMirror language packs and KaTeX's inlined fonts lazy (`test/viteChunks.test.ts`).
- Keyboard, overlay, IME and full-shell user journeys have real-browser coverage: `e2e/app-flows.spec.ts` (`e2e/app-harness.html` mounting the real `<App>` for open/edit/save, external conflict diffing, snapshot restore via `Mod+Shift+P`, `MediaLightbox` top-layer modal inspection, structural WCAG/ARIA checks, and `@axe-core/playwright` WCAG 2.1 AA audits across light/dark shells, Settings modal, and `MediaLightbox`), `e2e/a11y-ergonomics.spec.ts` (focus trap, `inert`, palette IME Enter guard, tree navigation, menu clamping), `e2e/topbar-tabs.spec.ts` (tablist semantics, sibling close button geometry, arrow navigation) and `e2e/ime-and-inline-boundaries.spec.ts` (CJK composition inside a heading/bold, caret geometry and Backspace across inline marks).

- Let Playwright start and stop Vite in the foreground (use a free `PW_PORT` per worktree; never run `pkill chrome`). The `webServer` command starts `node ./node_modules/vite/bin/vite.js` directly — an intermediate `pnpm dev` wrapper is one more process a group kill has to infer.
- `pnpm test:e2e` runs `scripts/runE2eSupervised.mjs`, never `playwright test` directly. The supervisor starts the Playwright CLI in its own process group with a per-run `--omd-e2e-run=<uuid>` tag and a private `TMPDIR`, then reaps that group plus the run's Chromium helpers on every exit path: normal completion, throw, `SIGINT`/`SIGTERM`/`SIGHUP`, closed stdout (`EPIPE` → 141), and the synchronous `process.on("exit")`. `e2e/processReaper.mjs` must stay importable from `node:*` only and synchronous: an `exit` handler cannot await. Matching uses the run tag, the run temp directory and the root PID/PGID — never an executable name, or a developer's installed Chrome and MCP browser sessions become targets. `test/e2eProcessSupervisor.test.ts` pins the selection rules and proves SIGTERM/EPIPE teardown with real OS processes.
- Standalone audits under `e2e/*.mjs` launch through `withManagedChromium(options, fn)` (`e2e/browserLifecycle.mjs`); a bare `chromium.launch` + `finally { browser.close() }` cannot run after `SIGPIPE` or a kill. `browserLifecycle.mjs` may import only `node:*`, `@playwright/test` and `./processReaper.mjs` (`test/e2eHarnessDeps.test.ts` enforces the dependency declaration side).
- Every bare import in an e2e harness file (`e2e/**`) must be declared in `apps/desktop/package.json`; keep shared CodeMirror dependency ranges in lockstep with `packages/engine` to reduce duplicate-resolution risk. Vite serves the harness from this package, but a warm `node_modules/.vite` dependency-optimization cache can reuse a previously pre-bundled module and hide a missing declaration. With a cold cache the dependency scan fails and the affected harness module cannot resolve its import. `test/e2eHarnessDeps.test.ts` checks both declaration and range drift; delete `apps/desktop/node_modules/.vite` and rerun `test:e2e` to exercise the cold path.
- For engine-owned behavior, also read the corresponding [engine guide](../../packages/engine/AGENTS.md) and run its checks. For IPC changes, follow [Rust verification](./src-tauri/AGENTS.md#verification) as well.
