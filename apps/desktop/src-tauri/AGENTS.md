# Desktop Tauri & Rust Host

> **Parent:** [`../AGENTS.md`](../AGENTS.md)
> **Scope:** Native filesystem/window/menu/export commands, guarded document IO, and Tauri configuration (`apps/desktop/src-tauri/**`).

## Module Organization

- Apply the root size policy, including inline tests. Extract command domains into focused modules instead of growing `lib.rs` or `workspace.rs`; keep `lib.rs` focused on setup and `tauri::generate_handler!`.
- Move large inline test modules into sibling files (follow `src/documents/tests.rs`).
- **Cross-platform Rust hygiene:** Never hardcode POSIX absolute paths (`"/tmp/..."`) in cross-platform tests — `Path::is_absolute()` is `false` on Windows; use `std::env::temp_dir().join(...)` or `tempfile::tempdir()`. Keep `#[cfg(...)]` visibility symmetric across macOS/Windows/Linux (do not `pub(crate) use` items only called by `#[cfg(target_os = "macos")]` tests, and guard OS-specific unused struct fields with narrow `#[cfg_attr(target_os = "...", allow(dead_code))]`). Guard shared invariants (such as rejecting directories in `replace_existing`) before entering OS-specific fallback branches.
- Use `cfg!(target_os = "macos")` for runtime checks and `#[cfg(target_os = "macos")]` to exclude platform-specific imports/items from compilation; combine conditions with `any(...)`, not `|`. `export_preview` routes to the platform backend. `export_page.rs` reads the shared PDF page contract from `packages/engine/src/export/printContract.json` and `printRules.css` (default A4 portrait, 16 mm margins, optional Letter, orientation, print backgrounds, header/footer off). CSS `@page` uses the final page box; native print backends (`export_pdf_macos.rs`, `export_pdf_windows.rs`, `export_pdf_linux.rs`) receive portrait paper dimensions plus an orientation flag and keep the PNG height cap out of paginated PDF printing.

## IPC Contract & Concurrency Rules

1. **Thin command boundary:** Follow the root IPC update contract. Validate argument names (Rust snake_case maps to JS camelCase), register commands in `tauri::generate_handler!`, and return `Result` or an explicit typed outcome rather than hiding errors.
2. **Enum variant camelCase trap:** `#[serde(tag = "kind", rename_all = "camelCase")]` on a Rust enum only renames variant tags, **not** struct variant fields. Add `#[serde(rename_all = "camelCase")]` on every struct variant with multi-word fields (`SaveDocumentResult`, `DiskSnapshot`) and assert the output with a `serde_json::to_string` unit test.
3. **Never block the main thread on IO:** Non-`async` commands run synchronously on the main thread and stall all queued IPC. Any command performing disk IO or blocking work must be `async fn` + `tauri::async_runtime::spawn_blocking` (only fast in-memory state or main-thread-required window/menu calls like `set_window_theme` / `set_recent_files` stay sync).
4. **Targeted window events (`emit_to`):** When emitting window-scoped events (`menu-command`, `open-file`, `workspace-changed`, `session-flush`), the frontend listener in `desktopServices.ts` must use `listenTarget()` (`EventTarget::AnyLabel`), because Tauri's default `listen()` matches `Any` and fires in every window.
5. **Cross-layer constants:** Use the root named-value policy; `apps/desktop/test/crossLayerConstants.test.ts` guards native/TS contract drift.

## Subsystem Contracts

- **Guarded document IO (`documents.rs`, `documents/save.rs`, `scoped_io.rs`):** Editor documents must use `stat_document`, `read_document`, `read_document_streaming`, `read_document_version`, and `save_document` (double-compare atomic write; regular-file reads open via `scoped_io::open_regular_file` using `O_NONBLOCK` + `fstat` on Unix so `/dev/zero` and writerless POSIX FIFOs fail immediately without blocking or racing; `DocumentVersionCache` stat-first `(mtime_ns, size)` fingerprint). The only other file commands are `scoped_io::read_custom_css` (`.css`, <=1 MiB) and `scoped_io::write_exported_html` (`.html`/`.htm`, <=`MAX_EXPORT_HTML_BYTES`): there is no general-purpose `read_file`/`write_file`, and adding one back re-opens arbitrary-path read/replace from the webview.
- **Per-window authorization (`auth_scope.rs`):** Grants are keyed by window label (workspace roots + single document files) and revoked in `WindowEvent::Destroyed`. Every listing/search/quick-open/mutation command takes the injected `tauri::WebviewWindow` and calls `assert_dir_authorized`; version history uses `assert_file_or_workspace_authorized`; `watch_paths` filters through `authorized_watch_path` and `watcher.rs` routes `workspace-changed` via `emit_to`; `read_document`/`read_document_streaming`/`save_document`/`allow_document_assets` record the file grant. A window is only authorized after `allow_workspace_dir`, so frontend callers must await it before any listing or watching.
- **Editor vs auxiliary windows (`windows.rs`):** `is_editor_window_label` excludes `omd-export-*` hosts. Flush targets, `ExitRequested`, menu routing, and the focus/destroyed handlers filter through it; a non-editor window returns from `CloseRequested` before `api.prevent_close()`. A close that arrives mid-flush is queued in `FlushGate`, never dropped, and each round's finish calls `app_lifecycle::drain_flush_followup`.
- **Window geometry (`window_bounds.rs`):** Persist logical (DIP) bounds with the `logical` flag; restore through `apply_bounds`/`builder_geometry`, which migrate legacy physical shards and clamp an offscreen placement onto a monitor. Never feed `outer_position`/`inner_size` (physical) straight into the builder (logical) — that doubled every window on 2x displays.
- **Export CSP:** The export document may run exactly one script, pinned by SHA-256 (`EXPORT_READY_SCRIPT_SHA256` in `export_host.rs`, `EXPORT_NATIVE_CSP_META` in the engine). Never restore `script-src 'unsafe-inline'`; editing the readiness script requires updating both hashes (`crossLayerConstants.test.ts` recomputes them).
- **Export readiness & capture scale (`export.rs`, `export_host.rs`, `export_windows.rs`):** `EXPORT_READY_TIMEOUT_SECS` is the single cross-platform readiness deadline; `EXPORT_TIMEOUT_SECS` (macOS) and `EXPORT_READY_TIMEOUT_MS` (Windows/Linux) derive from it — never reintroduce a per-platform literal, or one OS silently gives a heavy document 5 s less than the others. `ExportSpec::effective_gpu_capture_scale` owns the GPU-texture step-down and returns the `downsampled` warning; the Windows host must surface that warning (`.or(scale_warning)`), an image quietly rendered below the scale the user picked is a bug report waiting to happen. The method is `cfg(any(windows, test))` — compiled in tests on every OS, but macOS rasterizes through WebKit at a fixed scale and the WebKitGTK path keeps its own unrounded variant (it sizes the window from the raw measured height); widening the gate without a caller trips `-D warnings` dead-code on the other backends.
- **Snapshot durability (`workspace/snapshots.rs`):** Snapshots go through `crate::atomic_write`, are capped per file (10 MiB) and per directory (50 MiB; evict oldest first but always keep the newest), and step the millisecond stamp forward on collision. `MAX_SNAPSHOTS_PER_FILE` stays in `workspace.rs` for the cross-layer drift guard. Orphaned `.tmp*`/`.omd-save-*`/`.omd-rename-*` stages older than an hour are swept from app-owned directories at setup (`temp_sweep.rs`) and from a document's parent after a successful save.
- **Image & asset scope (`lib.rs` / `assets.rs`):** `write_image` requires `document_path`, validates magic bytes against extension, enforces `MAX_IMAGE_BYTES`, rejects symlinks/traversal, and writes only inside `<doc_dir>/assets/`. Call `allow_document_assets` after open/save; it calls `authorized_document_directory` first, because widening recursive asset scope for a path the window never opened/saved would expose the whole parent directory to the asset protocol.
- **Native menu (`menu.rs`):** Installs as global menubar on macOS only (`rebuild_from_state` no-ops off macOS). Window items (`window-minimize`, `window-zoom`, `window-fullscreen`, `window-bring-all-to-front`) use regular `MenuItem`s handled in `handle_window_command` — never `PredefinedMenuItem`. All other item ids/accelerators must match `commands.ts::MENU_TO_COMMAND` and `shortcuts.ts` (`test/crossLayerMenu.test.ts`).
- **Session flush & updater (`session_flush.rs`, `lib.rs`):** `prepare_update_restart` is `async` + `spawn_blocking` so `session_flush_ack` can arrive; it never exits on timeout and drains any queued quit/close follow-up afterwards. `update_capability` derives install support from runtime `bundle_type()` (MSI/deb/rpm are check-only `manualPackage`).
- **App lifecycle (`app_lifecycle.rs`):** `quit_app` and `restart_app` live here (not `lib.rs`) and both go through `FlushGate`; `restart_app` uses `request_restart` so `ExitRequested`/`Exit` still run and the `session end clean=true` marker is written — a bare `restart()` would make the next launch report an abnormal exit.
- **Pre-paint theme (`lib.rs::startup_window_theme`):** Reads persisted `settings.json` during `setup` and applies `window.set_theme` before first paint.
- **Recovery drafts (`workspace/recovery.rs`):** A record is a versioned header (`OMD-RECOVERY 1` + one-line JSON `{"path": …}`) followed by the raw document bytes, so the draft's identity is not the lossy filename; headerless legacy files are still read as raw contents with `path: null`, and a corrupt header is preserved verbatim rather than guessed. `list_recoveries` reads only the header (never the body) and hides the `.`-prefixed staging leftovers a crash can leave. Keys are opaque frontend-derived names; writes go through `crate::atomic_write`. Reject empty/`..`/slash keys before joining the recovery directory.
- **Logging & diagnostics (`logging.rs`, `logging/{session,fields,frontend}.rs`, `diagnostics.rs`, `diagnostics/redaction/`):** Logging is opt-in: the composition root reads `settings.json` **once** and passes `logging_preferences(&raw)` into `install()`; `effective_level(LoggingPreferences)` is a pure function, and `logging.rs` never touches settings IO. An opted-out install probes nothing, creates no directory, registers no plugin, and reports `LogDestination::Off` (not `degraded`); `OMD_LOG=off` reports `LevelOff`. Install the panic hook before `Builder::default()`; register `tauri-plugin-log` inside `.setup()` after `probe_writable` (degrading to `temp_dir()` then `disabled` without panicking). Scan previous-session markers after plugin registration and before writing this run's `session start`; compare `loggingGeneration` so an unlogged interval cannot reuse old markers, and use the previous PID file for a fallback destination. Format paths via `logging::path_field` / `paths_field` (neutralizing boundary markers); redact only at diagnostics export time, including `environment.txt`'s `log_dir`. Export collects only this writer's own names (`{stem}.log` and `{stem}_YYYY-MM-DD_HH-MM-SS.log`), decodes non-UTF-8 lossily, and lists unreadable files in `manifest.json`'s `skipped_logs` instead of failing the bundle. Both `log_frontend` and `export_diagnostics` use `async` + `spawn_blocking` for file IO. `documents/save.rs` logs one terminal result; `save begin` is Debug-only.

## Verification

```sh
cargo fmt --manifest-path apps/desktop/src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path apps/desktop/src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
```

- IPC changes also require desktop contract tests; payload changes need serialized-JSON casing assertions. Run `pnpm verify` for the binary link gate, especially before multi-domain merges.
