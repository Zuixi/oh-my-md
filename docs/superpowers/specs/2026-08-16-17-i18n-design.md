## 已确认决策

| 决策点 | 选择 |
|---|---|
| 语种范围 | 固定 2 个：zh-CN + en |
| 切换模型 | 运行时切换，无需重启 |
| 原生菜单 | 本地化；Rust 自持两张字符串映射，IPC 只传 locale code |
| 引擎 | 不引入 locale 系统；唯一用户可见文案走宿主 option |
| 运行时依赖 | 零新增（不引入 i18next / react-intl / FormatJS） |
| 响应式机制 | `useSyncExternalStore`（React 19 原生） |

## 1. 目标与非目标

### 目标

- 引入 zh-CN + en 双语种，**运行时切换不重启**，覆盖 webview UI、原生菜单、用户可见错误文案。
- 语种持久化于现有 settings；启动自动检测系统语言；Settings 提供 `auto / en / zh` 手动覆盖。
- 引擎保持框架无关；唯一用户可见文案（broken-image）改走宿主 option。
- 零新增运行时依赖。

### 非目标

- 不做 2 个语种之外的扩展（不建翻译协作流程、不接翻译框架、不做命名空间/扫描器）。
- 不做 ICU / 复数 / 性别（编辑器 UI 无需；真出现某条再加一个 5 行 plural fn）。
- 不做 RTL 布局（zh / en 均 LTR）。
- 不本地化引擎内部错误、调试日志、`eprintln!`。
- 不动 Edit 菜单的 `PredefinedMenuItem`（undo/redo/cut/copy/paste/select_all 由 macOS 系统本地化）。
- 不引入 E2E 套件（沿用现有「自动化单元/集成 + Rust 测试 + 前端构建 + 安装烟测 + 人工 QA」门槛）。

## 3. 用户流程和状态机

### Locale 状态机

- 存储值 `S ∈ { "auto", "en", "zh" }`，默认 `"auto"`。
- 运行值 `R ∈ { "en", "zh" }`。
- **启动**：读 `settings.locale` → 若 `auto`，`R = navigator.language` 以 `"zh"` 开头 ? `"zh"` : `"en"`；否则 `R = S`。置 `current = R`，并 `invoke("set_menu_locale", { locale: R })` 校正原生菜单（Rust `install()` 时先按 `en` 建菜单，前端 mount 后毫秒级校正）。
- **用户切换**（Settings 选 auto/en/zh）：写 `settings.locale = S`；若 `auto` 按 OS 解析 `R`；调 `setLocale(R)`。
- **`setLocale(R)`**：置 `current = R` → 通知 React 订阅者（`useSyncExternalStore` 触发重渲染）→ 持久化 settings → `invoke("set_menu_locale", { locale: R })` 重建原生菜单。
- **失败语义**：菜单重建失败仅 `console.warn`，不抛、不阻塞 webview 切换（非文档正确性路径）。

### 渲染重渲染模型

无顶层 React Provider。外部 store（`i18n/index.ts`）持有 `current` + listeners；组件 `const t = useT()` 经 `useSyncExternalStore(subscribe, getSnapshot)` 订阅，语种变更即重渲染。此机制正好规避 `apps/desktop/AGENTS.md` 反复警告的「一次性 window listener 捕获旧 state」陷阱。

## 4. TypeScript / Rust 接口及错误语义

### TypeScript

`apps/desktop/src/i18n/index.ts`：

```ts
export type Locale = "en" | "zh"
export type StoredLocale = "auto" | Locale

export function initLocale(stored: StoredLocale): void      // 启动解析 + 置 current + invoke set_menu_locale
export function setLocale(stored: StoredLocale): void       // 解析 + 置 + 持久化 + 通知 + invoke
export function getLocale(): Locale                          // useSyncExternalStore getSnapshot
export function subscribe(fn: () => void): () => void        // useSyncExternalStore subscribe
export function useT(): (key: string, params?: Record<string, string | number>) => string
```

- `t(key, params?)`：查 `messages[current][key]`；**缺失返回 `key` 本身 + dev `console.warn`，绝不抛**（保护渲染）；`{name}` 插值；无 ICU / 复数。

`apps/desktop/src/i18n/messages/en.ts`、`zh.ts`：

```ts
export const en: Record<string, string> = { "menu.file.new": "New", ... }
export const zh: Record<string, string> = { "menu.file.new": "新建", ... }
```

key 约定：扁平、点号分域（`menu.file.new` / `banner.saveConflict` / `find.placeholder` / `settings.language` / `topbar.unsaved`）。

`apps/desktop/src/settings.ts`：`UserSettings` 增 `locale: StoredLocale`；`DEFAULT_SETTINGS.locale = "auto"`；`sanitizeSettings` 将非法值收敛为 `"auto"`。

`apps/desktop/src/SettingsModal.tsx`：新增 Language 行（`<select>` 选项 `auto / en / zh`，显示名经 `t()`），`onChange` 走现有 `update({ locale })`，`onSave` 后触发 `setLocale`。

### 引擎（packages/engine）

复用引擎既有的 **Facet 注入函数模式**（`image.ts` 的 `imageResolver` Facet 持有一个 `(src: string) => string` 函数，由 `index.ts` 的 `EngineOptions.resolveImageSrc` 喂入，`editorExtensions(options)` 装配）：

- `packages/engine/src/index.ts` 的 `interface EngineOptions` 增可选 `imageBrokenLabel?: (src: string) => string`。
- `packages/engine/src/decorations/widgets/image.ts` 新增 `imageBrokenLabel` Facet（镜像 `imageResolver`：`Facet.define<(src: string) => string, (src: string) => string>`，`combine` 取末值，缺省返回 `(src) => \`🖼 ${src}（加载失败）\``），在 `editorExtensions` 中 `.of(options.imageBrokenLabel ?? defaultBroken)` 喂入。
- `ImageWidget.toDOM(view: EditorView)`（已接收 `view`）在 `onerror` 里调 `view.state.facet(imageBrokenLabel)(this.src)`，结果写入 `textContent`。
- **函数在失败时才调用**，读取的是注入闭包绑定的当前语种 → 运行时切换语种无需重建 view、无需 Compartment、无需逐标签追踪。默认（未传 option）保持现有字符串 → 兼容引擎独立测试。

引擎不导入 locale 模块，保持框架无关；桌面层 `Editor.ts` 装配 `editorExtensions` 时传入 `(src) => t("image.broken", { src })`，`t` 读取 i18n store 的 live `current`。

### Rust

`apps/desktop/src-tauri/src/menu.rs`：

```rust
struct MenuLabels { app_menu: &'static str, preferences: &'static str, /* ...各自定义标题 */ }
fn menu_strings(locale: &str) -> MenuLabels   // match "zh" => zh 表, 其它(含 "en"/未知) => en 表

struct MenuState { recents: Vec<String>, locale: String }  // Mutex, State::default (locale="en", recents=vec![])
fn rebuild_from_state<R: Runtime>(app: &AppHandle<R>, state: &MenuState) -> tauri::Result<()>
```

- `set_recent_files(app, paths: Vec<String>)`（现有）：锁 state → 更新 recents → `rebuild_from_state`。**行为不变**。
- 新命令 `set_menu_locale(app, locale: String) -> Result<(), String>`：锁 state → 更新 locale → `rebuild_from_state`。
- `install()` 初始 rebuild 用默认 `locale="en"`；前端 `initLocale` 后校正。
- IPC 字段 `locale` 单词，无多词字段 → 不触发 IPC casing 陷阱（仍加 Rust 测试断言 `menu_strings` 返回值）。

## 5. 安全、无障碍、性能与迁移约束

- **安全**：i18n 不引入新文件 / 网络 / IPC 授权面；`set_menu_locale` 是窄命令；`locale` 值由 `sanitizeSettings` 收敛，Rust `match` 未知 → `en`，不 panic。
- **无障碍**：`aria-label` / `placeholder` / `title` 全部纳入翻译；语种切换后焦点不丢失（`useSyncExternalStore` 重渲染保留 DOM 身份，不改组件 key）；Settings Language `<select>` 沿用现有 select 键盘模型。
- **性能**：两张扁平 `Record<string,string>` O(1) 查找；切换仅重渲染订阅组件 + 一次菜单重建（约 12 项），无感知；不引入懒加载（2 语种全量常驻，约 120 条）。
- **迁移**：`UserSettings.locale` 可选字段，`DEFAULT` 默认 `auto`，`sanitize` 兜底 → 向后兼容旧 settings（缺字段 → `auto`）；引擎 `imageBrokenLabel` 可选 option，缺省不变 → 兼容现有引擎测试。

## 9. 对后续规格提供的稳定接口

- `useT()` / `t(key, params)` / `setLocale` / `initLocale` / `Locale` / `StoredLocale` 类型——后续任何新增 UI 文案直接用。
- `menu_strings(locale)` + `set_menu_locale` 命令——后续新增菜单项只需加字符串。
- 引擎 `imageBrokenLabel`（函数注入）option——后续引擎新增用户可见文案沿用 host-option 函数注入模式（不在引擎内置 locale）。
- `UserSettings.locale` 字段稳定；后续若扩语种，`StoredLocale` 扩联合类型即可，`t()` / `menu_strings` 加分支。
