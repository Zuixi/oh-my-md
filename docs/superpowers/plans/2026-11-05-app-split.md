# App.tsx 拆解 P1–P5 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把五个高内聚职责（查找替换、文件树操作、文档打开链路、会话初始化、命令表）从 `App.tsx` 搬到独立模块，行为零变化，App.tsx 从 2832 行收缩到 ~1900 行。

**Architecture:** 绞杀者路径。每阶段只做「原样搬运 + 依赖注入」，复用仓库既有四种范式（动作模块 / 桥接工厂 / custom hook / 协调器）。终态方向（按领域分仓的 store/controller）见 spec §2，本计划只走过渡形态。

**Tech Stack:** React 19 hooks、TypeScript strict、Vitest + @testing-library/react。

**Spec:** `docs/superpowers/specs/2026-11-05-app-split-design.md`

## Global Constraints

- **测试即验收线**：`apps/desktop/test/` 下任何既有测试文件**禁止修改**。每阶段验收 = `pnpm --filter @omd/desktop test`（111 文件 / 1094 用例）全绿 + `pnpm --filter @omd/desktop exec tsc --noEmit` 通过 + `pnpm check:quality` 通过。
- **只搬不改**：函数体与注释原样搬运；不做顺手重构、不改格式、不重命名局部变量。
- **effects 不迁移**：所有 `useEffect` 及其依赖数组留在 `App.tsx`。
- **host 给 getter**：被抽模块对 App 状态的访问一律 `() => ref.current` 形式，禁止按值捕获。
- **基线只降不升**：`scripts/module-size-baseline.json` 中 `App.tsx` 条目每阶段结束时下调到当前实际行数（gate 禁止上调）。
- **新模块行数**：≤500 目标 / 800 硬上限。
- App.tsx 是唯一允许 `export default` 的文件；新模块全部命名导出。

### Task P1: `useFindReplace` — 查找替换 hook

**Files:**
- Create: `apps/desktop/src/useFindReplace.ts`
- Modify: `apps/desktop/src/App.tsx`（删除查找替换状态与函数，改用 hook）
- Modify: `scripts/module-size-baseline.json`（App.tsx 条目下调）

**Interfaces:**
- Consumes: `findReplace.ts` 的 `findNext`/`replaceOne`/`replaceAll`、`currentDocumentSearch.ts` 的 `makeSearchExtension`/`runSearch`、`findReplace.ts` 的 `FindQuery`、`currentDocumentSearch.ts` 的 `SearchRequest`。
- Produces: `useFindReplace(options)` hook，返回 App JSX 与命令表所需的全套查找替换 API（open/close/go/replace 等回调 + 各 state 值 + ref 镜像访问器），签名以搬运后 App.tsx 的实际调用为准；`getView(): EditorView | null`、`isActiveSafeMode(): boolean` 两个 getter 由 App 注入。

**Requirements:**
1. 搬走 App.tsx 中查找替换的**全部** state（`findOpen`/`findQuery`/`findReplace`/`findCase`/`findRegexMode`/`findWholeWord`/`replaceOpen`/`findIndex`）与镜像 ref（`findQueryRef`…`findIndexRef`、`findOpenRef`、`findRevisionRef` 等该组状态的全部 ref），以及函数 `closeFind`/`currentFindQuery`/`currentSearchRequest`/`realTextDoc`/`isActiveSafeMode`/`goFind`/`replaceCurrent`/`replaceEvery`。
2. `realTextDoc`/`isActiveSafeMode` 若被查找替换之外的代码使用，保留在 App 并由 hook 通过 getter 消费，或留在 App 仅供外部使用——以「查找替换逻辑进 hook、其余留在 App」划界，不许双向依赖。
3. `goFindRef`/`closeFindRef` 等「最新回调 ref」模式随函数一起搬进 hook。
4. App JSX 中 `<FindReplaceBar>` 的 props、命令表 `find`/`find-next`/`replace` 等条目的行为不变。

**验收（worker 自查后由 supervisor 复跑）:**
- `pnpm --filter @omd/desktop test`
- `pnpm --filter @omd/desktop exec tsc --noEmit`
- `pnpm check:quality`
- `wc -l apps/desktop/src/App.tsx` 预期 ≤ 2680（当前 2832）

### Task P2: `fileTreeActions` — 文件树操作桥接

**Files:**
- Create: `apps/desktop/src/fileTreeActions.ts`
- Modify: `apps/desktop/src/App.tsx`
- Modify: `scripts/module-size-baseline.json`

**Interfaces:**
- Consumes: `fileTreeState.ts` 的树模型操作（`setChildren`/`removeTreePath`/`emptyFileTree` 等）、`session.ts` 的 `findTabByPath`/`sessionDirty`/`sessionPath`、`documentMaterializer` 的 flush。
- Produces: `createFileTreeActions(host)` 工厂。`FileTreeHost` 接口全部为 getter/回调注入：`services`、`getTreeModel()`、`commitTree(next)`、`getWorkspace()`、`findTabByPath(path)`、`getContents(tabId)`、`flushMaterializer()`、`invalidateOpen(path)`、`isOpenInFlight(path)`、`closeTab(id, opts)`、`refreshTreePath(path)`、`notifySuccess(msg)`、`reportError(msg)`、`t(key, params)`（i18n 访问）、`confirm*` 系列。以搬运后能编译运行为准，宁少勿多。

**Requirements:**
1. 搬走函数：`refreshTreePath`、`refreshTree`、`toggleDir`、`expandToPath`、`createTreeFile`、`createTreeFolder`、`renameTreeEntry`、`deleteTreeEntry`，以及它们私有的命名辅助（`invalidName`/`normalizeMarkdownName`/`nextUntitledMarkdownName`/`reportTreeError`/`clearTreeError`、`revealFolder`/`chooseFolder` 若仅树使用则一并搬）。
2. **原样搬运**：`deleteTreeEntry` 内「在途打开作废」「confirm 前快照过期」的时序逻辑与注释逐字保留。
3. App 中调用点改为 `tree.refreshTree(listDir)` 等；effects（folder 变化加载、watch 轮询、workspace-change 监听）留在 App，内部改调工厂方法。
4. 工厂在 App 每次渲染用 `useMemo`（依赖稳定 refs）或组件外一次构造——选择与 `documentSaveAppBridge.ts` 相同的模式（对照该文件实现）。

**验收:** 同 P1 三连 + `wc -l` 预期 ≤ 2460。

### Task P3: `documentOpen` — 文档打开协调器

**Files:**
- Create: `apps/desktop/src/documentOpen.ts`
- Modify: `apps/desktop/src/App.tsx`
- Modify: `scripts/module-size-baseline.json`

**Interfaces:**
- Consumes: `documentScaleRegistry`（tier 评估）、`documentMaterializer`、`session.ts`、`constants.ts` 的 tier 阈值、`recoveryWriter`。
- Produces: `createDocumentOpen(host)` 协调器实例（类或闭包工厂，模式对照 `documentMaterializer.ts`）。**状态私有化**：`openRequestRef`（请求令牌）、`openInFlightRef`（在途路径集）、`invalidatedOpenPathsRef`（作废登记）改为协调器内部字段，host 通过 `currentRequest()`/`isOpenInFlight(path)`/`invalidateOpen(path)` 观察与干预。

**Requirements:**
1. 搬走函数：`resolveOpenTier`、`readSnapshotForOpen`、`openPath`、`runOpen`、`cancelOpening`、`openQuickOpen`、`openExternal`，以及 `OpenTier` 类型与 `awaitWithTimeout`（若仅打开链路使用）。
2. **状态迁移是本任务的解耦点**：三个 ref 从 App 的状态袋移入协调器；P2 的 `isOpenInFlight`/`invalidateOpen` 改为转发协调器。这是朝 spec §2 北极星演化的第一块自有状态。
3. `openingProgress`/`openingLabel`/`largeDocNotice` 等 UI state 留在 App，协调器通过 host 回调 `setOpeningProgress`/`setOpeningLabel`/`setLargeDocNotice` 上报——渲染状态归组合根。
4. `openRequestRef.current += 1`（卸载作废）由协调器 `dispose()` 完成，App 卸载 effect 调用之。
5. `loadLazyTab`、`activateTab`、`closeTabInternal` **不搬**（与 tab 生命周期纠缠，本阶段风险边界到此）。

**验收:** 同 P1 三连 + `wc -l` 预期 ≤ 2200。

### Task P4: `appSessionInit` — 启动序列动作

**Files:**
- Create: `apps/desktop/src/appSessionInit.ts`
- Modify: `apps/desktop/src/App.tsx`
- Modify: `scripts/module-size-baseline.json`

**Interfaces:**
- Consumes: `sessionRestore.ts`、`recoveryWriter.ts`、`settings.ts`、`windowScope.ts` 的 `isMainWindow`。
- Produces: `restoreSavedSessionFlow(host)`、`restoreDraftFlow(host)`、`loadInitialSettingsFlow(services)`（命名可微调）三个纯 async 动作函数，host 注入所需 getter/回调。

**Requirements:**
1. 搬走 `loadInitialSettings`、`restoreSavedSession`、`restoreDraft` 三个函数体（原样），host 提供 `services`、`getWorkspace()`、`commitWorkspace`、`resetTabDocument`、`activateTab`、`openPath`、`getDoc`、`setOpeningLabel` 等它们实际用到的访问器（对照函数体逐一列出，宁少勿多）。
2. **挂载 effect 不动**：App 的 mount `useEffect`（设置加载 → pendingOpen → 恢复的编排顺序）留在 App，只把内部调用改为新函数。
3. 分窗口 shard 语义（「每个窗口咨询自己的 shard；draft 恢复 main-gated」注释）逐字保留。

**验收:** 同 P1 三连 + `wc -l` 预期 ≤ 2080。

### Task P5: `appCommands` — 命令表数据化

**Files:**
- Create: `apps/desktop/src/appCommands.ts`
- Modify: `apps/desktop/src/App.tsx`
- Modify: `scripts/module-size-baseline.json`

**Interfaces:**
- Consumes: P1–P4 产出的全部 API、`commands.ts` 的 `AppCommand` 类型、`shortcuts.ts` 的 `shortcutFor`。
- Produces: `buildAppCommands(ctx: AppCommandsContext): AppCommand[]`。ctx 收全部已绑定回调（open/save/tab/theme/find/search/export/…），字段名以 App 现有闭包变量为准。

**Requirements:**
1. `allCommands` 数组 40+ 条目**逐条原样**搬入工厂函数体；每条的 `run` 闭包改为引用 ctx 字段，行为不变。
2. `runEditorCommand`/`runClipboardCopy`/`runClipboardPaste`/`insertImage`/`makeImageResolver` 若仅命令表使用则一并搬；若被 JSX/其他函数共用则保留在 App 并由 ctx 注入。
3. 全局 keydown effect 与 `commandsRef` 模式留在 App。
4. `crossLayerMenu.test.ts` 不受影响（它解析 engine keymap + `shortcuts.ts`，不碰 App.tsx）——验证方式就是它保持绿。

**验收:** 同 P1 三连 + `wc -l` 预期 ≤ 1940（±40 容差）。
