# Auto Pair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 omd 在正文与代码块里自动闭合括号/引号与 Markdown 标记（`*` `_` `` ` `` `$`），并提供跳越、成对删除与**三个**可热切换的用户开关（括号 / 引号 / Markdown 语法，D1）—— 全程不启用 stock `closeBrackets`。

**Architecture:** 引擎新增单文件 `format/autoPair.ts`：纯 `TransactionSpec` 判定（`EditorState` 上 headless 可测）+ 一个 `EditorView.inputHandler` 适配层 + 一个 `Compartment`（供热切换）。**没有 StateField、没有 effect、没有位置跟踪** —— 跳越用无状态启发式（spec §4.3 规则 3 有等价性论证）。三条路径（插入/跳越/删除）统一走 `state.changeByRange`，多光标与主光标同进同退（D10）。桌面侧只做设置持久化、UI、i18n 与视图热应用，复用 `Editor.ts` 的 `setEditorSpellcheck` 同款模式；语法知识留在引擎，用 Lezer 树判定。

**Tech Stack:** TypeScript, CodeMirror 6, Lezer Markdown, React 19, Vitest, Playwright(e2e)。

**Spec:** [`docs/superpowers/specs/2026-10-02-auto-pair-design.md`](../specs/2026-10-02-auto-pair-design.md)

## Global Constraints

- **不启用** `indentOnInput`、stock `closeBrackets`、通用 `autocompletion`（本计划实现的是引擎自研例外，与 `:` emoji completion 同类）。
- 引擎不得 import React / Tauri；DOM 只在 widget 里用。
- **不改 `parse/chars.ts`**：配对判定是字符串比较（`text === "("`），不是 `cx.char(...)` 数字码。
- 判定必须是**纯 spec**（输入 `EditorState` → `TransactionSpec | null`），dispatch 只在包装层 —— 与 `format/commands.ts::dispatchSpec` 一致。**硬不变量（R1）**：放弃路径（返回 null）绝不允许留下任何局部修改；适配层是唯一的 dispatcher。
- **跳越与插入必须用同一套「当前上下文里这个字符是不是配对符」的判断（D12）**：`isMarker && inVerbatim` 的标记不插入也不跳越；唯一的例外是成对删除（主动按键，不过滤）。
- 单键判定 O(1)：局部字符检查 + `syntaxTreeAvailable` + 一次 `resolveInner` 向上遍历；禁止 `forceParsing` / `ensureSyntaxTree` / 全文档扫描。
- readOnly 必须在命令层自查（`state.readOnly` → 返回 false）。
- `Prec.high` 的 Backspace 在「本次不适用」时必须 `return false`，让 `defaultKeymap` 的 `deleteCharBackward` / `skipAtomic` 继续工作。
- 事务 `userEvent`：插入 `"input.type"`，删除 `"delete.backward"`。
- settings 是不透明 JSON（`src-tauri/src/workspace.rs:305-317`），**不改 Rust**。
- 测试：`pnpm test`（引擎，含 `tsc --noEmit`）、`pnpm --filter @omd/desktop test`、`pnpm --filter @omd/desktop build`、`pnpm --filter @omd/desktop test:e2e`。
- Commit：`<type>: <why>`，无 `Co-authored-by`。

1. **规则 1 插入**：`(`→`()` 且光标居中；后接空白补（` bar`+`(`→`() bar`）；后接正文不补（`foo` 行首 `(`→null）；后接 `)` 补；**后接 CJK 句读补（D8）**：`这是测试|，` + `(` → `这是测试()，`，`foo|。` + `(` → `foo()。`；`’`/`】` 同理各一条（`」` 不在 D8 的集合里，不要为它写用例）；`\` 后不补；`'` 在 `don` 后不补、空白后补；`text.length !== 1` → null；`from/to` 与主选区不一致 → null。
2. **开关独立性**：只关 `quotes` → `(` 补、`"` 不补；只关 `brackets` → `"` 补、`{` 不补；`NONE` → 全不补。
3. **规则 2a**：`**` 后输入 `*` → 单插；并固定端到端序列 `*`→`*`→`bold`→`*`→`*` 逐步 update 收敛到 `**bold**`（spec §4.3 表格的可执行版本）。
4. **规则 2b（D11 收窄）**：空行首 `*` → null；空行首 `$` → null；**空行首 `` ` `` → 仍配对**；**空行首 `_` → 仍配对**；非空行（`foo` 后）`*` 仍配对。
5. **规则 3 跳越**：`()` 中间输入 `)` → 文档仍 `()`、光标 2；`*|*` 输入 `*` → 光标右移；关闭 `markdownSyntax` 后 `` `|` `` 输入 `` ` `` → 正常插入；后接字符之后是词字符时不跳（`(x)y` 位置 2 输入 `)` → 插入）；**CJK 后一位两个方向都要固定**：`中` 属于 `CharCategory.Word`（`charCategorizer` 的 `[\p{Alphabetic}\p{Number}_]`），所以 `"|"中` 输入 `"` → **不跳越**（插入），`"|"，` 输入 `"` → **跳越**；**D12 上下文过滤**：围栏代码块内 `` `x` `` 的收尾反引号前输入 `` ` `` → **返回 null（正常插入），不得跳越**；`$x$` 形式同理；同位置的 `)` 仍跳越。
6. **规则 4 成对删除**：`()` 中间 Backspace → 空；`(x|y)` → 只删一个；非配对位置 → null；`readOnly` → null；**刻意不过滤上下文**：围栏代码块内 `` `` `` 中间 Backspace → 删两个（固定这条不对称语义）。
7. **上下文（§4.4 / D9）**：`*` 在 `InlineCode`/`FencedCode`/`CodeBlock`/`InlineMath`/`MathBlock`/`FrontMatter` 内不补，同位置 `(`/`"` **仍补**；正文 `*` 补；**树未就绪**：detached `EditorState.create`（~20k 文本，按 `test/helpers.ts` 注释的 ~3k 同步解析边界）→ `syntaxTreeAvailable(state, end) === false` 且 `inVerbatim(state, end) === true` 且该处 `*` 不配对（fail-safe 方向固定）。
8. **多选区（D10）**：`EditorSelection.create([cursor(a), cursor(b)])`（`b` 为主）输入 `(` → 两处各得 `()`；其中一处位于空行首且输入 `*` → **整体返回 null**（断言 spec 为 null，而非「一处配对」）。
9. **放弃路径无副作用（R1）**：上一条的 null 情形下，spec 函数不得返回任何部分结果；`view.state` 引用不变（在 Step 5 的 view 用例里断言恒等 + `insert` 回调未被调用）。
10. **undo（review 项 B）**：state 带 `history()`，应用 `(` 的 spec 后调 `undo({ state, dispatch })` → 文档为空（一次撤销清掉 `()`）。
11. **端到端序列**：围栏代码块内逐字符输入 `foo({a: "b"})`，断言最终文本精确等于 `foo({a: "b"})`。

import { CharCategory, Compartment, EditorSelection } from "@codemirror/state"
import { syntaxTree, syntaxTreeAvailable } from "@codemirror/language"

const CLOSE_BEFORE = ")]}:;>，。、；：！？）】》”’"        // D8：CM6 集 + CJK 句读/闭符号
const EMPTY_LINE_MARKERS = new Set(["*", "$"])             // D11：只有这两个有块结构风险
const VERBATIM_NODES = new Set(["InlineCode", "FencedCode", "CodeBlock",
                                "InlineMath", "MathBlock", "FrontMatter"])
const BRACKET_PAIRS: Record<string, string> = { "(": ")", "[": "]", "{": "}" }
const QUOTE_PAIRS: Record<string, string> = { '"': '"', "'": "'" }
const MARKER_PAIRS: Record<string, string> = { "*": "*", "_": "_", "`": "`", "$": "$" }

export function inVerbatim(state: EditorState, pos: number): boolean {
  if (!syntaxTreeAvailable(state, pos + 1)) return true     // D9：树未就绪 → fail-safe 抑制
  let node = syntaxTree(state).resolveInner(pos, -1)
  for (; node; node = node.parent!) {
    if (VERBATIM_NODES.has(node.name)) return true
    if (!node.parent) break
  }
  return false
}

/** 逐 range 判定；任一 range 为 false 则整体放弃（D10）。
 *  已漂移：死参数 options 实现时已删（见上面的漂移注），shipped 签名为 (state, range, text, isMarker)。 */
function rangeAccepts(state, range, text, isMarker, options): boolean {
  if (!range.empty) return false                       // v1 不做包裹（Task 4 在此加分支持）
  const prev = range.from > 0 ? state.doc.sliceString(range.from - 1, range.from) : ""
  if (prev === "\\") return false
  if (text === "'" && /[A-Za-z0-9]/.test(prev)) return false
  const next = state.doc.sliceString(range.to, range.to + 1)
  if (next && !/\s/.test(next) && !CLOSE_BEFORE.includes(next)) return false
  if (isMarker) {
    if (prev === text) return false                                        // 2a
    if (EMPTY_LINE_MARKERS.has(text)) {                                    // 2b（D11）
      const line = state.doc.lineAt(range.from)
      if (line.text.slice(0, range.from - line.from).trim() === "") return false
    }
    if (inVerbatim(state, range.from)) return false                        // §4.4
  }
  return true
}

export function autoPairSpec(state, from, to, text, options): TransactionSpec | null {
  // 纯函数（R1）：只返回 spec，绝不 dispatch / 不碰 EditorView。
  if (state.readOnly || text.length !== 1) return null
  const main = state.selection.main
  if (main.from !== from || main.to !== to) return null   // DOM diff 只对应聚焦 range
  const isMarker = !!MARKER_PAIRS[text]
  if (isMarker) {
    if (!options.markdownSyntax) return null
  } else if (!((options.brackets && BRACKET_PAIRS[text]) ||
               (options.quotes && QUOTE_PAIRS[text]))) {
    return null
  }
  const close = BRACKET_PAIRS[text] ?? text               // 括号走映射表；引号/标记自配对
  let bailed = false
  const spec = state.changeByRange(range => {
    if (!rangeAccepts(state, range, text, isMarker, options)) {
      bailed = true
      return { range }                                    // 不改，稍后整体放弃
    }
    return {
      changes: { from: range.from, to: range.to, insert: text + close },
      range: EditorSelection.cursor(range.from + 1),
    }
  })
  if (bailed) return null          // 交回默认插入：所有光标都拿到裸字符（D10）
  return { changes: spec.changes, selection: spec.selection, userEvent: "input.type" }
}

export function autoPairExtension(options: AutoPairOptions): Extension {
  return [
    EditorView.inputHandler.of((view, from, to, text) => {
      if (view.composing || view.compositionStarted || view.state.readOnly) return false
      const spec = autoPairTypeOverSpec(view.state, from, to, text, options)   // 规则 3 必须先判
        ?? autoPairSpec(view.state, from, to, text, options)
      if (!spec) return false
      view.dispatch(spec)
      return true

      const spec = deletePairSpec(target.state, options)
      if (!spec) return false                       // 让位 skipAtomic / defaultKeymap
      target.dispatch(spec)
      return true

}
export function setAutoPair(options: AutoPairOptions) {
  return autoPairCompartment.reconfigure(autoPairExtension(options))

### Task 4（押后，可选）：选区包裹

**前置：** Task 1–3 已合并，且确认需要包裹（或需要 `~`/`=` 的 D2 语义）。

**内容：** 非空 range 分支在 `from`/`to` 两端插入（对齐 CM6 `handleOpen`），选区保留在中间；`~`/`=` 只在此分支生效（wrap-only，不插闭合），即恢复 D2 语义。

**必须同时验证的风险（原 D6）**：Live 模式下选区覆盖整段块 widget（代码块/表格/数学）时包裹是否产生破坏性结果；异常则加「选区与替换型装饰相交则跳过包裹」并在 spec §4.6 记结论。

**验收：** 选中 `word` 输入 `(` → `(word)`；选中输入 `~` → `~~word~~`、`=` → `==word==`；选中输入 `*` 只包一层（`*word*`）。
